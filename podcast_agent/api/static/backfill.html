Start enables the scheduled walk, which advances one month-window per podcast every 20 minutes until the window is exhausted. Pause takes effect at the next episode — the one in flight finishes first, so nothing is left half-written. It stops more than the next round: archive episodes already ingested are only ever advanced by a backfill run, so while paused they sit untouched rather than draining. A manual run still works while paused.

Recent episodes always go first. While anything from routine intake is still moving through the pipeline, the walk does not start, and a walk already running hands back at its next episode. That includes an episode waiting on local transcription, even though an archive month of transcript-only episodes would finish far sooner — the ordering is recency, not speed. It resumes on its own; nothing needs restarting.

Re-walk archive clears the cursors so the window is read again from the start. The walk only ever moves backwards, so a month it has already passed is otherwise unreachable — which matters after a change to what the walk collects. Nothing is deleted; only episodes that were never recorded are added.

Always dry-run first. The estimate is built from this deployment's own recorded latencies, not generic guesses. Every archive episode is recorded and triaged; whether one is summarised depends on the podcast having a transcript to work from — published, or made by transcribing locally — so the estimate separates the two.

How far back is set per podcast, in the History column on the Podcasts page — every podcast starts at 12 months and can be raised to 24 or 36 individually, because an evergreen interview podcast can repay three years where a daily news round-up does not repay one. Widening only adds months: the walk resumes where it stopped, nothing restarts, and narrowing deletes nothing already collected. It takes effect at the next run. Dry-run again after changing it.
