Models

Triage judges every episode from its description, so it wants to be cheap and fast. Summarise writes the summary you read, from a full transcript, so it wants to be capable and can afford to be slow. Fallbacks are tried in order when an endpoint times out, errors, or fails validation twice.

Local transcription

Speech-to-text runs in this process, on this machine, using faster-whisper — a CTranslate2 build of OpenAI's Whisper. (Configured under asr in config.yaml, the one place the older name survives.) Audio is downloaded to the work directory, transcribed, and deleted unless keep audio is set. Nothing is sent anywhere.

It is the last transcript strategy, tried only when a podcast publishes none — see the Transcripts column on Podcasts for which of yours actually need it.

Historical intake

Whether the archive transcribes a podcast is decided per podcast, by the Transcribe locally toggle on Podcasts. An archive episode with no published transcript, for a podcast not set to transcribe, is indexed and scored but never summarised — there is nothing to summarise from.

Prioritisation

How an episode is routed. Triage returns a relevance guess and a confidence that the description was informative enough to judge — these thresholds turn those two numbers into a decision, in code, never by the model.

Interests

Injected into every prompt and scored against by both tiers. Be specific — vague descriptions produce vague scoring. Weight is relative importance. Changing anything here means past scores were made under a different profile; the operations page will offer to re-score them.
