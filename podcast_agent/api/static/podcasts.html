What the columns mean

ColumnMeaning
Podcast Name, slug, and the podcast's own description taken from its feed at the last poll — so it follows the feed rather than needing to be maintained here. Beneath it, how often it publishes and whether it ships its own transcripts.
Transcripts How many of the last 25 episodes in the feed publish a transcript — measured at each poll, not declared in config. The line beneath says what that means given whether this podcast is transcribed locally, because the two together decide what a summary is actually built from. A podcast that publishes transcripts and also has local transcription on is not misconfigured: acquisition tries the published transcript first and only falls back to transcribing, so it simply never gets that far. The row worth acting on is none with local transcription off — those summaries come from descriptions alone.
Cadence Median gap between recent episodes, measured rather than declared — a weekly podcast that slips to fortnightly says so within a month or two. Read from the feed where possible, falling back to the episodes held. Hover for the measurement. Needs 3 dated episodes before it will guess.
Priority A hint passed to the triage prompt, not a hard filter. It colours how the model reads a thin description; it does not guarantee or prevent anything.
Always escalate Every episode gets the full treatment regardless of the triage verdict — for podcasts where you would rather pay than miss something.
Transcribe locally A fallback, not a mode. Acquisition always tries the published transcript first, then a configured scrape, and only then transcribes the audio itself — so turning it on for a podcast that publishes transcripts costs nothing, because it is never reached. On: the audio is downloaded and transcribed on this machine when the podcast publishes no transcript — accurate but slow. Off: a published transcript is used if one exists, otherwise the episode is summarised from its description and labelled description only. Governs the weekly pipeline.
Archive mode How the historical intake walk treats this podcast. No effect on weekly digests — see the three values below. (backfill_mode in config.yaml.)
History How far back historical intake reaches for this podcast. Every podcast starts at 12 months; raise it for the ones whose back catalogue is worth having — an evergreen interview podcast can repay three years where a daily news round-up does not repay one. Widening only adds months: the walk resumes where it stopped, and narrowing deletes nothing already collected. (backfill_months in config.yaml.)
Episodes Total held for this podcast, and how many are still moving through the pipeline. Nothing is ever deleted, so this only grows.

Routine polling only looks forward, so on its own it holds roughly the last two weeks. Everything older arrives from historical intake, which records every archive episode and triages it, whether or not it publishes a transcript. What a missing transcript costs is a summary, not a place in the list: those episodes are indexed and scored, never summarised, while local transcription is off.
Feed health Result of the last poll. After 5 consecutive failures the circuit opens and polling backs off to daily.
Intake Whether new episodes are taken in at all. Disabling keeps everything already summarised; episodes already queued still finish.

Turning Transcribe locally on is what lets the archive transcribe this podcast's back catalogue — hours of CPU per podcast, so it is a decision made one podcast at a time rather than a single global switch.
